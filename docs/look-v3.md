# Look v3 — the surface rig

**Lane:** poppy · **File:** `client/src/look.rs` · **Switch:** `VOXELFORGE_LOOK_GEN`
· **Frames:** `docs/assets/look/`

The brief was "the lighting has to beat a modern Minecraft shader pack", scoped
to **surfaces, characters and objects** — the sky-dome/atmosphere lane is closed
and nothing here touches it. v3 adds no sky, no post-process filter and no new
render pass; it changes how light *arrives at a surface*.

## What actually changed

| | v2 (before) | v3 (after) |
|---|---|---|
| ambient | flat `AmbientLight` 1150 lux + 2 directional fills | **hemispherical environment map** (diffuse *and* specular) + flat floor cut to 380 lux + the same 2 fills |
| character separation | none | **camera-relative cool kicker**, 600 lux, no shadow map |
| soft shadows | PCSS at High/Ultra, width 8.0 | PCSS at **Medium and up**, width **12.0** |
| contact shadows | 0.75 blocks / 0.20 thick / 16 steps | **1.10 / 0.14 / 24** |
| near cascade | 16 blocks | **10 blocks** |
| SSAO | Low / Low / High / Ultra | Low / **Medium** / **Ultra** / Ultra |
| bloom | emissive only (threshold 1.0) | threshold **0.85**, low-frequency boost **halved** to 0.35 |

The headline is the first row. `AmbientLight` and `DirectionalLight` both feed
the **diffuse** term only; an environment map also feeds the **specular** one.
That is the difference between a lit surface and a painted one, and it is what
every reference pack in `_poppy_lookv2/ref/` has that this frame did not.

Two design notes worth reading in the source:

- **The irradiance is transferred, not added.** A uniform hemisphere of
  luminance `L` delivers `π·L` lux, so the 260 cd/m² map is ~817 lux — almost
  exactly the 770 lux taken out of the flat term. Four representative shaded
  surfaces land within 3 % of their v2 totals (table on `IBL_NITS_DAY`). The
  point is not more light; it is that the fill now arrives **from a direction**,
  so a shaded ground face and a shaded underside stop receiving the identical
  number. Orientation is the only shape cue a cube has.
- **The kicker is the one light in this file that knows where the camera is.**
  Every other light describes the world. This one describes the *shot*: "behind
  the subject" is a fact about the camera, and a world-fixed rim lights a
  silhouette from one orbit angle and a face from the opposite one.

### Why `VOXELFORGE_CINE` and not `VOXELFORGE_LOOK_CAM`

The orbit boom is pulled in by terrain collision, and on the Edhari campsite it
is pinned hard enough that `LOOK_CAM` yaw 0 / 90 / 180 / 270 all render the same
wall — measured, `_poppy_lookv3/scout/cam_*.png`. A pair shot through it would
be perfectly honest and show nothing. `CINE` writes the gameplay camera's
transform outright, so both frames of a pair are provably the same pose.

## Measured

`python scripts/_poppy_lookv3_pairs.py docs/assets/look` — the numbers table is
in `docs/look-v3-numbers.txt`, regenerated by that script. It checks two things:
that each pair is actually two different pictures (a harness that writes the
same frame twice produces a very reasonable-looking nothing), and then the axes
this change is allowed to move.

## Sweep hooks — every v3 knob is reachable without a rebuild

| var | effect |
|---|---|
| `VOXELFORGE_LOOK_GEN=v1\|v2\|v3` | which generation of the rig runs (unset ⇒ v3) |
| `VOXELFORGE_LOOK_IBL=off\|<nits>` | lift out / sweep the environment light |
| `VOXELFORGE_LOOK_RIM=off\|<lux>` | lift out / sweep the kicker |
| `VOXELFORGE_LOOK_PCSS=off\|<width>` | penumbra width |
| `VOXELFORGE_LOOK_CONTACT=off\|<l,t,s>` | contact march |
| `VOXELFORGE_LOOK_SSAO`, `_SSAOQ` | AO thickness / quality |

`VOXELFORGE_LOOK_GEN=v2` reproduces the 2026-08-14 rig **byte-for-byte** out of
the same binary: every v3 fork in `look.rs` goes through one predicate (`v3()`),
and the v2 arm of each is the untouched original expression.

## What this does NOT claim

- Nothing here re-grades. `TEMPERATURE`, `POST_SATURATION`, `ev100`, `sky_gain`
  and the haze curve are untouched; the frame's colour identity is whatever the
  last grade pass signed off.
- The environment map is a 1×1-per-face hemisphere, i.e. a *gradient*, not a
  capture of the actual surroundings. It cannot reflect the ruin you are
  standing next to. Real local reflections would be `ScreenSpaceReflections`,
  which is a separate cost conversation and is not in this change.
- No sky, dome, atmosphere or fog-volume code was touched.
