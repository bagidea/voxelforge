## อันดับ 12 · เงาของเราเป็น "แดงเลือด" ไม่ใช่เงา — `post_saturation 1.90` ดันสีออกนอก gamut แล้วโดน clamp — **Rose** (+ Kevin)

### สิ่งที่ตาเห็น
เปิด `palette-clip-proof-2026-08-08.png` — **ขอบเงา รอยต่อบล็อก และร่อง AO ทุกเส้นในทั้ง 3 เฟรมติดม่วงหมด**
ส่วน golden ref สะอาด **0.0%**. คนทั่วไปไม่ได้เห็นเป็น "หลุด palette" — เขาเห็นเป็น *"ทำไมเกมนี้เหมือนโดนฟิลเตอร์
Instagram ทับ / ทำไมทุกอย่างจุ่มเลือด"* ซึ่งเป็นความรู้สึก "ไม่ AAA" ที่ตรงที่สุด

### วัดได้

|---|---|---|---|---|
| **golden ref** | **0.0%** (144 px) | — | — | — |
| wide-hero-final | 2.8% | — | — | — |
| boot | **9.3%** | **(44, 5, 1)** | 94.2% | 35 / 34 / 31 |
| walk | **9.6%** | — | — | — |
| combat | **11.8%** | **(49, 14, 1)** | 88.5% | 22 / 31 / 48 |

`look-bible` §4 กำหนดเงาเป็น **warm brown-violet `#2A2030` = (42, 32, 48)** — ของเราเรนเดอร์ออกมา **(44, 5, 1)**
ค่า L ใกล้กัน (9.4% vs 16%) แต่ **G ถูกบีบจาก 32 → 5 และ B จาก 48 → 1**. ไม่ใช่ "เงาเข้มไป" (นั่นคือ G3 ที่วัดแล้ว)
แต่คือ **เงาผิดสี** — และกระจายเท่ากันทั้งเฟรม (35/34/31) จึงไม่ใช่ artifact เฉพาะจุด

หญ้าเป็นอาการเดียวกันคนละด้าน: พิกเซลเขียวทั้ง 3 เฟรมมี **B เฉลี่ย 1.2–2.5 จาก 255** และค่าที่พบบ่อยที่สุดคือ
`(0, 108, 0)` เป๊ะๆ — saturation 0.97–0.99 เทียบสเปก foliage 0.39 (**+57 ถึง +59 pp**).
**ไม่ใช่ความผิดของ albedo:** `sim/src/block.rs` เก็บ grass `#5b8c46` (sat 0.33), leaves `#3a7436` (0.36),
moss `#4b6e37` (0.33) — ทั้งสามอยู่ในสเปกอยู่แล้ว. สีนีออนเกิดตอนเรนเดอร์

### กลไก (คำนวณได้ ไม่ใช่เดา)
`client/src/look.rs` → `grade::POST_SATURATION = 1.90`. Bevy ทำ post-saturation เป็นการผสมรอบ luminance:

```
c' = L + (c − L) × sat          L = 0.2126R + 0.7152G + 0.0722B
```

`sat > 1` ผลักช่องที่ **เป็นเสียงข้างน้อย** ออกห่าง L → ติดลบ → ถูก clamp เป็น 0.
**การ clamp คือการเปลี่ยน hue ไม่ใช่การเพิ่ม saturation** — สีนั้นเลิกเป็น "ตัวเองที่อิ่มขึ้น" ทันที

รัน `clip_forecast()` ใน `scripts/palette_break.py` กับ anchor ของ look-bible ที่ **sat 1.90**:

| สีที่ป้อน | ออกมา | ช่องที่ clip |
|---|---|---|
| foliage `#8A8A3C` (138,138,60) | **(143, 143, 0)** | **B** |
| teal accent `#4FC9D6` (79,201,214) | **(0, 223, 248)** | **R** |
| sun-key `#F4B860` (244,184,96) | **(255, 178, 11)** | **R** |
| sun-key-hi `#FFD98A` (255,217,138) | (255, 215, 65) | R |
| เงาเข้มสุดที่ gate ประกาศเอง (45,22,7) | **(62, 19, 0)** | **B** |

→ **4 ใน 11 สีหลักของ look-bible เรนเดอร์ออกมาตรงตามที่เขียนไว้ไม่ได้เลย** ภายใต้ค่าที่ ship อยู่
รวมถึง **teal accent ซึ่งเป็นสีเย็นสีเดียวของทั้งเกม** (look-bible §4 บอกว่าเป็นตัวตัดให้ภาพมีชีวิต)

ที่ **sat 1.35** เหลือแค่ sun-key/sun-key-hi ที่ clip R (ปลายไฮไลต์ — รับได้) · ที่ **sat 1.15** เหลือ sun-key-hi ตัวเดียว

> **ความซื่อสัตย์ของหลักฐาน:** ตาราง forecast เป็นเลขคณิตบนค่าคงที่ที่ ship ในสเปซ sRGB 8-bit ส่วน Bevy
> ทำ post_saturation ใน tonemapping shader ซึ่งสเปซทำงานอาจไม่ตรงกันเป๊ะ. **forecast จึงบอกว่า "สีไหนเสี่ยง"
> ส่วนที่ยืนยันว่า "เกิดขึ้นจริง" คือเลขที่วัดจากเฟรม** (B เฉลี่ย 1.2–2.5, พิกเซลหลุด palette 9.3–11.8% โดย 88–94% อยู่ที่ hue < 2.5°).
> สองทางชี้ตรงกัน จึงเชื่อได้ — แต่ตัวเลข "หลังแก้" ต้องยิงเฟรมใหม่มาวัด ไม่ใช่คำนวณ

### ทำไมมันถึงเล็ดลอดทุก gate
คอมเมนต์ที่ `look.rs:440-450` บันทึกไว้เองว่าไต่ sat จาก 1.05 → 1.90 เพื่อไล่แกน `sat` และ `warmth` ให้ผ่าน
— และสังเกตแล้วด้วยว่า "saturation pushes RED DOWN บนหญ้า (green-px mean R 65.1 → 41.3)".
สิ่งที่ยังไม่มีใครวัดคือ **อีกฝั่งของ clamp**: การบีบ G/B ให้เป็น 0 บนพิกเซลอุ่น **ทำให้ R−B ขึ้นสูงสุด**
→ **แกน warmth ของ gate ได้คะแนนเพิ่มจากความเสียหายโดยตรง** นี่คือ Goodhart's law เต็มรูปแบบ

### ทางเลือก (เสนอ 3 แบบ — ผมเชียร์ B)
| | ทำอะไร | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A** | ลด `POST_SATURATION` 1.90 → **1.35** | แก้ที่ต้นเหตุ จุดเดียว · anchor กลับเข้า gamut หมดยกเว้นปลายไฮไลต์ · **มี env lever อยู่แล้ว ไม่ต้อง build** | แกน `sat`/`warmth` ในสกอร์การ์ดจะตกลง — ต้องหา warmth คืนจาก *สีของแสงและ haze* (ซึ่ง `look.rs:440` เขียนไว้เองว่าเป็นที่ที่ถูกต้อง) |
| **B** ✅ | **A + ชดเชย warmth ด้วย key/ambient colour แทน global sat** (`VOXELFORGE_LOOK_LIGHT` มีอยู่แล้ว) | ได้ทั้ง gamut และตัวเลข · ตรงกับข้อสรุปที่ทีมเขียนไว้เองว่า "chroma ต้องมาจากแสงกับอากาศ ไม่ใช่ตัวคูณ global" | ต้อง sweep 2 แกนพร้อมกัน (sat × light colour) — งาน A/B ไม่ใช่งานคิด |

## อันดับ 13 · ฟ้าเป็นแผ่นสีเดียวแปะหลังฉาก — ไม่มี gradient ไม่มีหมอกที่เส้นขอบฟ้า — **Shiba** (gradient = Rose)

### สิ่งที่ตาเห็น
ทั้ง 3 เฟรม ฟ้าคือ **สี่เหลี่ยมสีฟ้าค่าเดียว** ตัดกับบล็อกเป็นเส้นคมเป๊ะ ไม่มีอะไรจางเข้าหากันเลย
— อ่านออกทันทีว่าเป็น "ฉากหลังกระดาษแข็ง" ไม่ใช่ท้องฟ้า และมันคือที่เดียวในเฟรมที่ตาไปพัก

### วัดได้
| | ฟ้ากิน % เฟรม | L เฉลี่ย | **L ส่วนเบี่ยงเบน** | **gradient จอมฟ้า→ขอบฟ้า** | **ความคมของเส้นขอบฟ้า** |
|---|---|---|---|---|---|
| boot | 5.31% | 60.8 | **±4.14** | **+1.12 pp** | 13.8 pp |
| walk | 7.22% | 61.6 | **±3.06** | **+0.37 pp** | 8.8 pp |
| combat | 2.98% | 60.3 | ±4.57 | +10.26 pp * | 16.4 pp |

\* combat เลขสูงเพราะฟ้าถูกตึกหั่นเป็นเศษคนละความสูง จึงไปจับค่าเงาของตึก ไม่ใช่ gradient จริง — **อย่าใช้เป็นหลักฐานว่าผ่าน**

ส่วนเบี่ยงเบน **±3–4.6 pp ทั่วผืนฟ้า 59,000 พิกเซล** = แผ่นเรียบ. ท้องฟ้าจริงไล่ค่า 15–25 pp จากจอมฟ้าลงขอบฟ้า

### ต้นเหตุ (ยืนยันจากโค้ด)
- `client/src/main.rs:399` → `ClearColor(Color::srgb(0.53, 0.72, 0.92))`
- `client/src/look.rs:1316` `apply_look_to_cameras()` เขียนทับด้วย `h.sky × h.sky_gain` ตามชั่วโมง
- **`grep -rn "Skybox" client/src sim/src` = ไม่พบ** → ในเรโปไม่มี skybox / ไม่มี gradient / ไม่มี cloud layer เลย
  ฟ้าคือ **ค่าคงที่ค่าเดียวต่อเฟรม** ตามนิยาม

> **ไม่ทับข้อ 3 ของเมื่อวาน:** ข้อ 3 คือ atmospheric perspective *ของฉาก* (near/far localRMS ของบล็อก)
> ข้อนี้คือ *ตัวผืนฟ้าเอง* — ต่อให้ fog ในข้อ 3 ลงครบ ฟ้าก็ยังเป็นแผ่นเดียว เพราะ `ClearColor` อยู่นอกทางเดินของ fog

### ต้องทำ (เรียงจากถูกไปแพง)
1. **gradient แนวตั้ง** ให้ผืนฟ้า: จอมฟ้าเข้ม → ขอบฟ้าสว่างและซีดลง ต่างกัน **≥ 12 pp** — เป็นค่าใช้จ่ายเกือบศูนย์
   (fullscreen quad หลังฉาก หรือ skybox 2 สี) · **Rose** = ตัว shader, **Shiba** = เลือกคู่สีให้อยู่ในโทน golden-hour
2. **แถบหมอกที่เส้นขอบฟ้า** — ให้บล็อกไกลสุดจางเข้าหาสีฟ้าล่าง (ใช้ haze ตัวเดียวกับข้อ 3 ได้ ประหยัดงาน)
   จนขั้นที่รอยต่อ **≤ 6 pp**
3. **ปิดรูฟ้าที่ขอบบนเฟรม** — ซ้ำกับข้อ 2 ของเมื่อวาน (ทำครั้งเดียวได้ทั้งสองข้อ)
4. **อย่าเพิ่งใส่เมฆ** — ก่อนมี gradient เมฆจะกลายเป็นสติกเกอร์บนกระดาษแข็ง จัดคิวไว้หลังข้อ 1

**เกณฑ์รับ:** ผืนฟ้ามี gradient จอมฟ้า→ขอบฟ้า **≥ 12 pp** และ **ขั้นที่เส้นขอบฟ้า ≤ 6 pp** ในช็อตกลางแจ้งทุกใบ
วัดด้วย `python scripts/palette_break.py` (บรรทัด `sky`)

> **หมายเหตุที่ต้องพูดตรงๆ:** look-bible §4 เขียน sky-day ไว้ที่ `#BCD3E0` (L 81) เราเรนเดอร์ที่ L 60 —
> แต่ `look.rs:1316` **ตั้งใจ** เขียนทับให้เข้มกว่า โดยให้เหตุผลว่าฟ้าที่ไม่เข้ากับ key light คือจุดที่ทำให้เฟรมดูปลอมที่สุด.
> เป็นการตัดสินใจที่มีเหตุผลบันทึกไว้แล้ว **ผมจึงไม่ตั้งค่า L เป็นเกณฑ์รับ ไม่รื้อของที่ตัดสินไปแล้ว** —
> เกณฑ์อยู่ที่ *ความแบน* กับ *ความคมของขอบฟ้า* ซึ่งไม่มีใครเคยตัดสินใจ มันแค่ยังไม่มี

## ❌ ข้อที่ผมตรวจแล้ว "ไม่เสนอ" — เพราะพิสูจน์แล้วว่าตัวเองคิดผิด

**"เฟรมเราแดงเกินปลายอุ่นของ palette"** — สมมติฐานแรกของผมตอนดูภาพ. วัดแล้ว **ตกเกณฑ์ (ก) ทันที**:
พิกเซล hue < 27.5° (แดงกว่า anchor อุ่นสุด) — เรา **45.1–65.4%** แต่ **golden ref เอง 79.4%** และ
wide-hero-final **75.8%** คือ *แดงกว่าเราอีก*. เกณฑ์นี้แยก ref ออกจากเราไม่ได้ → **ทิ้ง ไม่ใช่ประตูส่งงาน**
(ฟังก์ชัน `warm_overshoot()` ยังอยู่ในสคริปต์ในฐานะ **ตัวชี้วัดอ้างอิง** เผื่อใครคิดสมมติฐานนี้ซ้ำ จะได้เห็นเลยว่ามันตก)

**เพิ่ม saturation / เพิ่ม warmth / เพิ่มความอิ่มสีหญ้า** — ตรงข้ามกับสิ่งที่ควรทำ ดูข้อ 12
