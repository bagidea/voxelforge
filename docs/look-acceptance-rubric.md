## วิธีใช้ (อ่านก่อนเกรด)

1. **เครื่องมือที่ต้องมี:** โปรแกรมเปิดรูปที่มี **eyedropper อ่านค่า RGB/luminance** (Photoshop/GIMP/Krita/แม้แต่ Paint.NET) + **zoom ได้ 400%+**. ไม่ต้องมีอะไรพิเศษกว่านี้.
2. **Luminance (L)** ในเอกสารนี้ = ค่าความสว่างสัมพัทธ์ 0–100% คำนวณจาก `L = (0.2126·R + 0.7152·G + 0.0722·B) / 255 × 100` (R/G/B เป็น 0–255). ถ้า eyedropper อ่าน HSL "L" ให้ก็ใช้ค่านั้นได้เลย (คลาดกันเล็กน้อย ยอมรับได้).
3. 🚨 **เฟรมจากโหมด `--play` ต้องล้าง HUD ก่อนเข้า grader เสมอ — ไม่มีข้อยกเว้น.**
   รัน `python scripts/_flamingo_dehud2.py <frame.png>` แล้วเกรดไฟล์ `-nohud2.png` ที่ได้.
   เหตุผล (เจอจริง 2026-08-04): เฟรม `--play` เผา HUD ติดมา 3 จุด — แถบ FPS/HP/ST บนซ้าย,
   crosshair กลางจอ, และบล็อกข้อความ `[E] …` กลางล่างที่เป็น**ตัวอักษรขาว ~250 วางทับพื้นดินจริง**.
   ผลคือ grader อ่าน UI แทนการเรนเดอร์:
   - **G5** จับ "พิกเซลสว่างสุด" ได้ที่ `(15,12) RGB=(255,255,255)` = ตัวอักษร `FPS` → **FAIL ปลอมทุกเฟรม**
   - **p95** ถูกดันด้วยตัวอักษร ไม่ใช่ไฮไลต์
   - **micro-contrast** พองขึ้นจาก hard edge 1px ของฟอนต์บนผิวเรียบ (วัดได้ 9.7–10.9 ดิบ · **5.2–5.8** หลังล้าง)

   `_flamingo_dehud2.py` ตั้งเกณฑ์แบบ **"สงสัยว่าเป็น UI = ลบ"** โดยเจตนา — ลบพลาดโดนไฮไลต์จริง
   ทำให้คะแนน**ต่ำลง**ได้เท่านั้น ดันขึ้นไม่ได้ ⇒ เป็นการทำให้เกตเข้มขึ้น ไม่ใช่หย่อนลง.
   (`_flamingo_dehud.py` ตัวเก่าตัดแค่แถบบน+crosshair — **ไม่พอ** ห้ามใช้เกรดเฟรม `--play` แล้ว)
4. **เกรด 2 ชั้น — อ่านให้เข้าใจ:**
   - **ชั้น A · GATE (6 ด่าน):** ตกด่านใดด่านหนึ่ง = **FAIL ทั้งเฟรมทันที** ไม่ต้องคิดคะแนนต่อ. ด่านพวกนี้คือ "แกน identity" ที่หายแล้วลุคตาย.
   - **ชั้น B · AAA SCORE (100 คะแนน):** คิดต่อ **เฉพาะเฟรมที่ผ่าน gate ครบ** — ให้คะแนนถ่วงน้ำหนักตาม 9 pass + geometry เพื่อบอกว่า "AAA แค่ไหน".
5. **ให้คะแนน pass:** แต่ละ pass มี sub-check ย่อยพร้อมเกณฑ์ตัวเลข. `เต็ม` = ผ่าน sub-check ครบ · `ครึ่ง` = ผ่าน sub-check หลักแต่พลาดข้อรอง · `0` = พลาด sub-check หลัก. ตัวเลขต่อ pass อยู่ในหัวตาราง.
6. **จุด sample คงที่:** เพื่อเทียบซ้ำได้ ใช้จุดเดิมทุกครั้ง (นิยามในแต่ละ pass). ถ้า Poppy จัดบล็อกต่างจาก ref เล็กน้อย ให้ sample "บริเวณเชิงหน้าที่เดียวกัน" (เช่น จุดมืดสุดในร่ม, patch โดนแดดตรง).

## P0 Axis Targets — machine-graded (`scripts/grade_axes.py`)

> **แกนตัวเลขที่เครื่องเกรดเองได้ ไม่ต้องพึ่งตา.** ใช้เป็นด่านคัดก่อนคนไล่ GATE — รันแล้วได้ PASS/FAIL รายแกน + verdict รวม + exit code (0=ผ่านหมด).
> **`scripts/grade_axes.py` คือ single source of truth ของเลขพวกนี้** (ตาราง `TARGETS` ในหัวไฟล์เกรดจริง). ตารางล่างนี้เป็นสำเนาให้คนอ่าน — ถ้าแก้เลข ต้องแก้ **ที่สคริปต์** แล้ว sync มาที่นี่.
>
> รัน: `python scripts/grade_axes.py <frame.png>` (รับหลายเฟรมได้). ทุกแกนวัดบน resample 1024×1024 เหมือน `grade_beauty.py` — เทียบข้ามเรนเดอร์ได้.

| แกน | นิยาม | target | REF (golden) | แก้ปัญหาลุคอะไร |
|---|---|---|---|---|
| **warmth R−B** | midtone-band mean (R−B) | **≥ +110** | +120.9 | โทนอุ่น golden-hour — กันภาพเย็น/ซีด |
| **blue B** | midtone-band mean B | **≤ 10** | 4.3 | กัน blue-wash ในร่ม |
| **saturation** | midtone-band mean sat % | **≥ 90%** | 96.1 | สีอิ่ม ไม่จืด/หม่น |
| **DOF fg:bg** | hi-freq std ratio fg/bg | **≥ 3.0** | 3.50 | แยกระยะ ชามคม–ฉากหลังฟุ้ง |
| **micro-contrast** | hi-pass std (GaussianBlur r3) บน 1024-L | **≥ 5.0** | 5.24 | รายละเอียดผิว/เกรน ไม่เบลอเนียนตาย |
| **highlight p95** | global luminance p95 (~170 band) | **150–185** | 165.8 | หน้าต่างสว่างพอดี ไม่คลิป/ไม่ทึม |

> **midtone band** = พิกเซลที่ luminance L อยู่ช่วง [p35, p75] — คือ "เนื้อไม้ที่โดนไฟ" ของเฟรม (ตัด highlight/shadow สุดขั้วออก).
> **⚠️ target ชุดนี้ re-derive แบบ "ปิด gap เข้าหา REF" (2026-07-26).** target เดิม `≥+175 / ≤18 / ≥88` เป็น **phantom** — คนละเมตริกกับที่สคริปต์วัด และ REF เองวิ่งเข้าไม่ถึง → ถ้าใช้จะ reject spike ที่ถูกจริง. ทิ้งแล้ว. เกณฑ์ปัจจุบันพิสูจน์กับ ref: **ref เกรดตัวเอง 6/6 PASS** (ดู [P0-axes calibration log](#p0-axes-calibration-log-phantom-target-retired) ท้ายเอกสาร).

## ชั้น A — GATE CHECK (6 ด่าน · binary · ตก 1 = FAIL)

ตกข้อไหน = เฟรมไม่ผ่าน ไม่ว่าคะแนน AAA จะสูงแค่ไหน. เกณฑ์ทั้งหมดอ่านจากรูปเดียวได้.

| G# | ด่าน (จาก pass-list) | วิธีวัดจากรูปเดียว | PASS เมื่อ | FAIL เมื่อ |
|---|---|---|---|---|
| **G1** | **Voxel hard-edge geometry** | zoom 100% ดูขอบวัตถุ (ชาม/เคาน์เตอร์/ตู้) | ขอบเป็น 90° อ่านออกว่าเป็น "บล็อกลูกบาศก์" ทุกวัตถุหลัก — ไม่ถูก bevel/round/smooth หาย | วัตถุดูกลม/เนียนจน identity voxel หาย |
| **G2** | **Key light มีทิศชัด** (pass 1) | หาแถบแสงหน้าต่าง/เงาทอดบนพื้น | เห็น **ทิศแดดเดียว** ชัด + มีแถบแสงกรอบหน้าต่างทาบพื้น/ผนัง | แสงแบนไร้ทิศ / ไม่มีแถบแสงหน้าต่างเลย |
| **G3** | **Bounce ในร่มไม่ดำ + ไม่ฟ้า** (pass 2) | วัด **5th-percentile luminance ของพื้นที่ในร่ม** (ตัดขอบเฟรมนอกสุด 8% ทิ้ง เพื่อเลี่ยง crevice มุมภาพ) + eyedrop จุดมืดสุดเช็คโทน | **p05-L ≥ 8%** **และ** จุดมืดสุดยัง "เห็นเนื้อไม้" **และ** โทนอุ่น (R ≥ G ≥ B) | p05-L < 8% (ร่มถูกบดเป็นดำทั้งเฟรม) **หรือ** B > R (ร่มออกฟ้า/เย็น) |
| **G4** | **Soft shadow + contact AO** (pass 4) | zoom 400% ที่ขอบเงาทอดยาว + ดูจุดชาม/วัตถุแตะพื้น | ขอบเงา transition **≥ 3px** (ไม่คม 1px) **และ** มีเงาเข้มจุดสัมผัส (AO) ใต้วัตถุ | ขอบเงาคม 1px ทั้งภาพ **หรือ** วัตถุ "ลอย" ไม่มี contact shadow |
| **G5** | **Tone-map ไม่ blow-out** (pass 6) | sample 3 จุดไล่ลงช่องหน้าต่าง + ดูว่าเป็นแผ่นขาวตันไหม | **≥1 ใน G/B ของจุดสว่างสุด ≤ 245** (ไม่ใช่ขาวนวล 255,255,255) **และ** 3 จุด L ต่างกัน ≥ 8 (เห็น gradient) | หน้าต่างเป็นแผ่น flat ≥250 ทั้ง R,G,B / gradient หาย — (R เดี่ยวแตะ 255 ได้ ถ้า G,B ยัง roll-off เป็น golden-hour ปกติ) |
| **G6** | **Warm golden tone** (pass 1+9) | eyedrop **patch พื้นไม้/เคาน์เตอร์ที่โดนแดดตรง** — เอา patch **ที่สว่างที่สุดในบรรดา patch ที่ hue ผ่าน** | **(ก) hue อุ่น:** R > G > B และ R−B อยู่ **40–210** (วัดที่ **ผิวไม้** — albedo อุ่นดัน B ต่ำกว่าค่า "สีไฟ") **และ (ข) โดนแดดจริง:** **L ≥ 55%** ของ patch นั้น | **(ก) ตก:** โทนเย็น/ขาว (B ≥ G **หรือ** R−B < 40) **หรือ** ส้มเทียมจัด (R−B > 210) — **หรือ (ข) ตก:** L < 55% ⇒ สีถูกแต่ **ไม่มีผิวไหนสว่างพอจะนับว่า "โดนแดด"** (แดดจำลอง/exposure ต่ำ) |

> **G3 + G5 คือด่านที่พลาดบ่อยสุด** ในงาน voxel-shader — ร่มดำตัน กับ หน้าต่างขาวคลิป. ให้ eyedrop จริง อย่าเชื่อสายตา (จอสว่างต่างกันหลอกตาได้).
>
> ⚙️ **เกณฑ์ตัวเลข G3/G5/G6 + Pass 1b ผ่านการ calibrate กับ golden ref แล้ว (2026-07-25)** — ดู [Calibration log](#calibration-log-dry-run-กับ-golden-ref) ท้ายเอกสารว่าปรับจากค่าไหน เพราะอะไร.
>
> ⚙️ **clause (ข) `L ≥ 55%` ของ G6 เขียนเพิ่มเมื่อ 2026-08-04** — ไม่ใช่เกณฑ์ใหม่ แต่เป็นการ **ดึงเอกสารให้ตรงกับเครื่องมือ**: `scripts/grade_gate.py` บังคับ `L ≥ 55` มาตั้งแต่ commit แรก (`7afc7e9`) ⇒ คำตัดสิน G6 ทุกครั้งในโปรเจกต์นี้คิด floor นี้อยู่แล้ว แต่ตารางข้างบนจดแค่ hue. ดู [G6 sunlit-floor reconciliation log](#g6-sunlit-floor-reconciliation-log-doc-ตามหลัง-tool-2026-08-04).

> 🔻 **`scripts/grade_hero.py` = ADVISORY เท่านั้น ไม่ใช่ผู้ตัดสิน G3/G5/G6 (ลดชั้น 2026-08-07).**
> **ผู้ตัดสินคือ `scripts/grade_gate.py` ตัวเดียว** — เวลาสองตัวไม่ตรงกัน ให้ยึด `grade_gate.py`.
> เหตุผล: การ sample ของ `grade_hero.py` ถูกจูนไว้กับเฟรมเดียว (ครัว hero tight ในร่ม) แต่เพลตชุด
> Edhari ปัจจุบัน **เป็นกลางแจ้งทั้งหมด** ⇒ มันออกคำตัดสินบนสิ่งที่ไม่ใช่หัวข้อของด่านเงียบๆ:
> G5 ค้นเฉพาะกล่องซ้ายจอ ("หน้าต่างอยู่ซ้าย") ซึ่งกลางแจ้ง = **ท้องฟ้า**, และ G6 **ไม่มี floor `L ≥ 55`**

> ติดขอบเฟรม / อยู่ในแถบฟ้า / เป็นสีฟ้า / ไม่มีบริเวณ near-neutral ให้จับเลย → รายงาน **`UNRELIABLE`
> แทน PASS/FAIL** (และ `regrade.py` จะอ่านเป็น "ไม่มีคำตัดสิน" ไม่ใช่ค่าผิด). สิ่งที่ยังใช้ประโยชน์ได้จาก

## ชั้น B — AAA SCORE (100 คะแนน · คิดเฉพาะเฟรมที่ผ่าน gate)

## รวมคะแนน + เกรด

**รวม AAA Score = Σ ทุก pass = ____ / 100**  *(ฐาน 100; ถ้ามี pass N/A แบบ Lite ให้ปรับฐานด้านล่าง)*

| คะแนน (จากฐานเต็ม) | เกรด | คำตัดสิน |
|---|---|---|
| **90–100** | **AAA** | ส่งได้เลย — ลุคถึงเป้า golden beauty-shot |
| **78–89** | **AA** | ใกล้มาก — ไล่เก็บ pass ที่ได้ "ครึ่ง/0" ตามน้ำหนักสูงก่อน (2 → 4 → 6) |
| **65–77** | **A** | ลุคมาถูกทาง แต่ยังห่าง AAA — โฟกัส GI(2)+shadow(4) เป็นอันดับแรก |
| **< 65** | **B / ต่ำกว่า** | ยังไม่ใช่ลุค Voxelforge — แม้ gate ผ่าน ก็ยัง "แค่มี shader" |

> **หมายเหตุสำคัญ:** เฟรมที่ **ตก gate = FAIL** เสมอ **ไม่ว่าคะแนน B จะสูงแค่ไหน** — คะแนนสูงบวก gate ตก แปลว่า "สวยผิดทาง" (เช่น bloom จัดจนหน้าต่างคลิป).

### การปรับฐาน Lite (เมื่อมี pass N/A)
ถ้าเกรด **Lite non-hero** และปิด DOF (pass 5 = N/A ตาม tier spec): เอา 8 คะแนนของ pass 5 ออกจากฐาน →
**เกรดจากฐาน 92** แล้วเทียบ %: `AAA ≥ 90% ของฐาน (≥ 83) · AA ≥ 78% (≥ 72) · A ≥ 65% (≥ 60)`.
Pass อื่นที่ Lite ตัดได้ (volumetric god ray→screen-space ยังต้องเห็นแท่ง, dust particles) **ไม่ปลด N/A** — ต้องเห็นผลชั้นนั้นแม้ทำด้วยเทคนิคถูกกว่า. **แกน gate ทั้ง 6 ห้าม N/A ทั้ง Ultra และ Lite.**
