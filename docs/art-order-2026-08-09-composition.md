# ใบสั่งงานอาร์ต — ช่องว่าง AAA ที่สคริปต์วัดไม่ได้

**Flamingo (Designer) · 2026-08-09 · เรียงตาม "ตาคนธรรมดาเห็นความต่างมากที่สุด"**

Scorecard วัดสี/แสง/เงาไปหมดแล้ว และ **ผ่าน**. ส่วนที่ยังห่าง AAA อยู่คนละแกน —
มันคือ **การจัดองค์ประกอบและอาร์ตไดเรกชัน** ซึ่งไม่มี gate ตัวไหนแตะเลย.
ทุกข้อข้างล่างมีตัวเลขของตัวเอง. ข้อที่ตาคนธรรมดามองไม่เห็นความต่าง **ผมตัดทิ้งแล้ว** (ดู §ตัดทิ้ง).

## ⚠️ อ่านก่อน 3 ข้อ

**1. ไม่มี "ลุคกลางแจ้ง" ที่ใครเซ็นอนุมัติเลย — นี่คือรากของปัญหา.**
เฟรมที่อนุมัติมีสองใบ (`golden-beauty-shot-ref.png`, `wide-hero-final.png`) และ **ทั้งคู่เป็นห้องในร่ม**.
ผมวัดแล้ว: ทั้งสองใบมี **sky pixel = 0** และ **cold-hue pixel = 0**.
แต่เฟรม gate3 ทั้งสามใบเป็นกลางแจ้ง มีฟ้า 3.1–7.4% ของเฟรม.
เรากำลังเกรดฉากกลางแจ้งด้วยไม้บรรทัดของห้องครัว — มันเลย "ผ่าน" แต่ยังไม่ AAA.

**2. เฟรม gate3 ที่ใช้อ้างอิงมีอายุ 4 วัน (2026-08-05 15:38) และ look stack ขยับไปแล้ว.**
ที่สำคัญคือ `POST_SATURATION` 1.90 → **1.02** (`client/src/look.rs:578`, ลงวันนี้).
→ ข้อ **A6 (หญ้านีออน) ต้องยิงเฟรมใหม่ก่อนตัดสิน** ห้ามให้ใครไปทาสีหญ้าใหม่ตอนนี้.
ข้อที่เหลือ (A1–A5, A7, A8) มาจาก **source/map ที่ HEAD** ไม่ใช่จากเฟรม → อายุเฟรมไม่กระทบ.

**3. เลนไฟล์.** `docs/LANES.md` ระบุเจ้าของไว้ต่างจากที่ Director แบ่งงาน (Kevin=วัสดุ / Monanisa=ตัวละคร / Shiba=ฉาก).
ทุกข้อผมใส่ทั้ง **คนทำอาร์ต** และ **เจ้าของเลนที่ต้องขอ ack ก่อนแก้ไฟล์** ไว้ให้แล้ว — อย่าข้ามเลนเงียบๆ.

## A1 · ท้องฟ้าเป็นแผ่นสีทาไว้ ไม่ใช่บรรยากาศ 🔴 เห็นชัดที่สุด

**คนทำ: Shiba (ฉาก/สี)** · เลนโค้ด: `client/src/look.rs` = **rose** (ต้องขอ ack)

| วัด | ค่า |
|---|---|
| ฟ้าในเฟรม gate3 | 19,902–34,905 px (3.1–7.4% ของเฟรม) |
| **gradient แนวตั้งของฟ้าทั้งผืน** | **+0.3 / −0.8 / −1.4 L** (boot/walk/combat) |
| สีที่ออกจอ | RGB (121,150,191) |
| **look-bible.md:126 สั่งไว้** | **`#BCD3E0` = (188,211,224) "pale warm blue"** |
| ในโค้ด | ไม่มี `Skybox`, ไม่มี dome, ไม่มี gradient shader — มีแค่ `ClearColor` (`main.rs:399`) ที่ `look.rs:1582-1587` เขียนทับด้วยสีเดียวแบน |

ฟ้าไล่เฉด **0.3 หน่วยความสว่างทั้งผืน** = มันคือสีทาบนผนัง ไม่ใช่ท้องฟ้า.
และมันคือ **ของที่สว่างที่สุดในเฟรม** (rubric:118 บอกเองว่า 99% ของ p95 คือฟ้า) —
ของที่สว่างที่สุดในภาพเป็นแผ่นแบน ตาจะอ่านว่า "เกมไม่มี shader" ทันที
ซึ่งคือนิยาม FAIL ที่ `look-bible.md:111` เขียนไว้เป๊ะๆ.

**สั่งงาน**
1. **ทันที (ไม่ต้อง build):** เพิ่ม hook `VOXELFORGE_LOOK_SKYGAIN` — ตอนนี้ `VOXELFORGE_LOOK_SKY` แก้ได้แค่ hue
   ส่วน `sky_gain: 2.4` (`look.rs:757-758`) **ไม่มี env lever** → A/B ฟ้าไม่ได้เลยถ้าไม่ใส่ hook. หนึ่งบรรทัด.
2. **ของจริง:** sky dome / far-plane quad ที่ไล่เฉด 3 จุด — zenith → horizon → **horizon เชื่อมเข้าสีหมอก**
   (`FOG_COLOR_DAY = [0.94,0.66,0.26]` ส้มทอง) ตามที่ `look-bible.md:41,67` สั่งว่า "ระยะไกลจางเป็นหมอกทอง"
   และ `look-contract.md:40` สั่งว่า "ขอบโลกละลายเข้าฟ้าเงียบๆ".
3. **เกณฑ์รับ (วัดด้วย `art_order_grade.py`, ดู A9):**
   `sky gradient` **≥ 25 L** · `sky ramp is monotonic` **≥ 0.85** · `horizon seam step` **≤ 12 L**
   — ทั้งสามข้อพร้อมกัน. ทิศทางไม่บังคับ: golden hour ขอบฟ้าสว่างกว่า zenith ได้ (grader วัดขนาด
   แล้วรายงานว่าปลายไหนสว่าง). ผมพิสูจน์บนเฟรม boot จริงแล้วว่าถ้าทา ramp 32 L ลงไปในผืนฟ้าจริง
   grader อ่านได้ **29.8 L / mono 1.00 / seam 3.4** = ผ่านทั้งสามข้อ → **เส้นนี้ผ่านได้จริง ไม่ใช่เส้นลอย**

## A2 · god ray มีโค้ดครบ แต่ไม่เคยเรนเดอร์ออกมาสักเฟรม 🔴 คุ้มที่สุดในลิสต์

**คนทำ: rose (`look.rs`) + poppy (`scene.rs`)** — งานเอนจิน ไม่ใช่งานอาร์ต แต่เป็นตัวเปลี่ยนหน้าตาเฟรมมากที่สุด

`VolumetricFog` ใส่บนกล้องแล้วที่ High (`look.rs:1517-1522`, 32 steps) และ Ultra (`look.rs:1530-1537`, 96 steps).
`VolumetricLight` ใส่บนดวงอาทิตย์แล้ว (`look.rs:1699-1707`).
แต่ Bevy จะ scatter **เฉพาะข้างใน `FogVolume`** — และทั้ง repo มี `FogVolume` อยู่ที่เดียว: **`client/src/hero.rs:662`**
ซึ่งคือฉากถ่ายรูปในร่ม. path `--play` ไม่ spawn เลย.

→ **ray-march วิ่งอยู่ในสุญญากาศทุกเฟรม. เกมจริงไม่มี god ray ที่ tier ไหนเลย.**
gate3 ยิงด้วย `VOXELFORGE_PLAY=1` (`scripts/gate3_shoot.sh:175`) = อยู่ใน path นี้เป๊ะ.

**หลักฐานยืนยัน:** `hero.rs` เป็นฉากเดียวที่ **เห็น god ray จริงในภาพ** และมันก็เป็นฉากเดียวที่ spawn `FogVolume`
(`hero.rs:31, 662`). ถ้า `VolumetricFog` + `VolumetricLight` พอสำหรับ Bevy รุ่นนี้ ฉาก hero คงไม่ต้อง spawn มัน.

god ray + dust motes คือ **element เอกลักษณ์ของ ref** (`golden-beauty-shot.md` pass #3, rubric:156-157) —
เรามีโค้ด มีค่า tune ไว้หมด ขาดอย่างเดียวคือ **spawn entity เดียว**.
comment ในโค้ดเชื่อว่ามันทำงานอยู่ — `look.rs:1503-1506` บอกว่า High ยอมทิ้ง PCSS เพื่อ "เก็บ volumetric ray-march ไว้
เพราะบรรยากาศคือสิ่งที่ตรึงเฟรม" และ Ultra เขียนว่า "full-step god rays".
**เจตนาถูก โค้ดครบ แต่ตัวกลางไม่มี → จ่ายค่า ray-march 32/96 steps ทุกเฟรมโดยไม่ได้อะไรกลับมา.**
(เท่ากับ A2 คืนทั้งภาพและเฟรมเรต — ถ้าไม่ spawn ก็ควรถอด VolumetricFog ออกจาก High/Ultra ไปเลย)

**สั่งงาน:** spawn `FogVolume` + `Transform` ครอบพื้นที่เล่นในฉาก play. คุมความหนาให้ "เห็นเป็นแท่ง ไม่ใช่ fog ทึบทั้งจอ" (rubric:156). ทำ A/B ก่อน/หลังด้วยกล้องเดิม.

**เกณฑ์รับ — สองชั้น ต้องผ่านทั้งคู่:**
1. **source gate:** มี `FogVolume` อย่างน้อย 1 จุดนอก `hero.rs` (grader เช็คให้)
   → **ผ่านแล้ว: `client/src/look.rs:2023` (rose, ยังไม่ commit ณ 2026-08-10)**
2. **pixel gate — ต้องส่งเฟรมคู่ กล้องเดิม เท่านั้น** (เฟรมเดียวตัดสินไม่ได้ เหตุผลใน A9):
   `shaft amplitude` **≥ 6 L** · `not a global lift` **≤ 0.35** · `shaft elongation` **≥ 3.0** ·
   `coverage` **0.5–25%** ของเฟรม
   ```
   VOXELFORGE_LOOK_VFOG=off  ... -> before.png      # rose ใส่คันโยกไว้แล้ว look.rs:1993
   (default)                 ... -> after.png
   python scripts/art_order_grade.py --frame after.png --before before.png
   ```
   เกตนี้ยิงลำแสงสังเคราะห์ 18 L ผ่าน, 2 L ตก, glow กลม 25 L ตก, exposure ยกทั้งจอ 8 L ตก,
   กำแพงหมอกเต็มจอ 12 L ตก — พิสูจน์ว่ามันวัด "ลำแสง" ไม่ใช่ "สว่างขึ้น"

`maps/edhari.json` คือแมพที่ gate3 ถ่ายทุกใบ (`scene.rs:41` `PLAY_MAP`). นับจริงจากไฟล์:

| วัด | ค่า |
|---|---|

วัสดุที่มี BRDF ต่างจริงมี 4 ตัว — **wood** (satin เดียวในเกม, rough 0.58/refl 0.34),
**obsidian** (โปร่งแสง+สะท้อนตัวเดียว, alpha 0.66/refl 0.92), **lamp** (emissive ตัวเดียว), **snow**.
แมพใช้ **ศูนย์ตัว**. เรนเดอร์เรามีของเล่น 4 อย่าง แมพไม่หยิบสักอัน.
(`lamp` ยังเรียกไม่ได้ด้วยซ้ำ — `BlockId::name()` ไม่มี entry `"lamp"` โหลดเดอร์ parse ไม่ผ่าน)

**สั่งงาน (ทำตามลำดับนี้ ได้ผลไวสุด)**
1. **แตกกำแพงหิน** — เอา `cobblestone` / `brick` / `limestone` แทรกใน run ที่ยาว ≥8 ให้เป็นชั้น/แถบ
   (ตอนนี้มี 46 คอลัมน์ที่เป็นหินยาว 12 ก้อนติดไม่มีรอยต่อเลย)
2. **ใส่ wood ให้บ้าน** — บ้าน 8 หลังเป็นหินล้วน ทั้งที่ wood คือวัสดุ satin ตัวเดียวที่เรามี
3. **ฆ่าสนามโล่ง** — 56% ของ footprint ไม่มีอะไรเลย: โรย `moss`/`dirt`/`gravel` เป็นหย่อม + `leaves` เป็นพุ่ม
   ให้ midground มีของให้ตาเกาะ
4. **`lamp`** — เปิดชื่อใน `BlockId::name()` แล้ววางเป็นจุดไฟอุ่นตอน golden hour = จุดพักสายตาที่ ref มี เราไม่มี
   *(ตำแหน่งเป๊ะ: `LAMP` ถูกประกาศฝั่ง client เท่านั้น — `client/src/voxel.rs:77` `pub const LAMP: BlockId = BlockId(16)`;
   ฝั่ง sim ไม่มี `BlockId::LAMP` เลย → `ALL_PLACEABLE` (`sim/src/block.rs:35-51`) ไม่มีมัน และ `name()` คืน `"unknown"`
   โหลดเดอร์แมพเลย parse คำว่า `lamp` ไม่ได้. คอมเมนต์ `voxel.rs:76` เขียนเองว่า "a one-line change and is in the report" —

5. อัปเดต `maps/FORMAT.md` — ตอนนี้เอกสารลิสต์ block id แค่ 0–4 อีก 10 ตัวไม่เคยถูกเขียนถึง
   **นี่น่าจะเป็นเหตุผลที่ไม่มีใครเคยใช้มันเลย**

## A4 · ไม่มี aerial perspective — ของไกลคมกว่าของใกล้ 🟠

**คนทำ: rose (`look.rs`)** · ปรับได้ด้วย env ไม่ต้อง build

`DistanceFog` **เปิดอยู่และ tune แล้ว** ทุก tier (`look.rs:1439`) — แต่ `HAZE_START = 20.0` (`look.rs:112`),
คือ **ไม่มีหมอกเลยในระยะ 20 บล็อกแรก**. เฟรมเกมเพลย์เกือบทั้งหมดอยู่ในระยะนั้น → หมอกไม่ทำงาน.

วัดบนเฟรม boot (ปีกซ้าย/ขวา = ของใกล้, กลางเฟรม = ปลายถนน — ยืนยันด้วยตาแล้ว):

| | sat | local contrast |
|---|---|---|
| ไกล (กลางเฟรม) | 0.787 | **6.96** |
| ใกล้ (ขอบเฟรม) | 0.917 | **2.81** |
| **อัตราส่วน ไกล/ใกล้** | 0.86 | **2.47×** |

ถ้ามีมิติจริง ตัวเลขนี้ต้อง **ต่ำกว่า 1.0** ทั้งคู่ — ของไกลต้องจางกว่า.
ตอนนี้ของไกล **คมกว่าของใกล้ 2.5 เท่า** = ภาพแบนเป็นแผ่นเดียว ตาแยกชั้นไม่ออก.

**สั่งงาน:** A/B `VOXELFORGE_LOOK_FOG=6,90` (ดันจุดเริ่มหมอกเข้ามาในระยะที่กล้องเห็นจริง) เทียบกับ default
ด้วยกล้องเดิม แล้ววัดอัตราส่วนเดิมซ้ำ. ไม่ต้อง build.

**เกณฑ์รับ:** `far/near local contrast` **< 0.80** (grader ใช้แถบ y บน 1/3 เทียบล่าง 1/3 ตัดฟ้าออก
— camera-independent ต่างจากตาราง "กลาง/ปีก" ข้างบนที่เลือกช่องด้วยตา, grader พิมพ์ค่านั้นให้เป็น advisory คู่กัน).
positive control: **golden ref ที่อนุมัติแล้ววัดได้ 0.49 ✅** — เส้นนี้เฟรมที่ผ่านตาคนอนุมัติผ่านได้จริง
(หมายเหตุ: `wide-hero-final` วัดได้ 3.66 ❌ แต่ `aaa-framing-spec.md:145` เขียนเองว่าเฟรมนั้น
"the light gate passes but the geometry is broken" → อนุมัติที่แสง ไม่ใช่ที่การจัดวางระยะ)

**frame class (สำคัญ — A4 เป็นเกตของ environment shot เท่านั้น):** grader ไม่ auto-detect ว่าเฟรมเป็น
"hero portrait" หรือ "environment" จากเลข magic อีกต่อไป — คนยิงเฟรมต้องประกาศเองด้วย `--frame-class`.
- `--frame-class environment` (default) → วัด `far/near local contrast < 0.80` ตามปกติ
- `--frame-class portrait` → A4 **SKIP โดยดีไซน์** (hero close-up ไม่มีของไกล/ของใกล้ให้วัด — ไม่ใช่ PASS ไม่ใช่ FAIL)

**ห้ามลด threshold 0.80 เพื่อให้ hero portrait ผ่าน** — ถ้าลด เส้นจะอ่อนต่อ environment shot จริง

## A9 · บรรทัดตัดสิน — **ปิดแล้ว** `scripts/art_order_grade.py` (2026-08-10)

`palette_break.py` / `depth_layering.py` **วัดครบแต่ไม่เคยตัดสิน** — ไม่มี threshold, ไม่มี `sys.exit`,
ไม่มีคำว่า PASS สักที่ → งานที่ส่งกลับมาตัดสินได้ด้วยตาอย่างเดียว. ตอนนี้มีเส้นตัดแล้ว:

```
python scripts/art_order_grade.py                      # เฟรม gate3 + แมพ + source gate
python scripts/art_order_grade.py --frame after.png --before before.png \
       --idle boot.png --hero-box x0,y0,x1,y1
python scripts/art_order_grade.py --calibrate          # ชุด control อย่างเดียว
```

**exit code:** `0` ผ่านหมด · `1` มีข้อตก · `2` ใช้คำสั่งผิด · `3` **calibration พัง (ห้ามเชื่อผลใดๆ)** ·
`4` **INCOMPLETE — มีเกตที่วัดไม่ได้ ซึ่งไม่นับว่าผ่าน**

### กฎ 3 ข้อที่ไฟล์นี้บังคับด้วยโค้ด ไม่ใช่ด้วยวินัย

**1. calibrate ก่อนเชื่อ — ทุกครั้ง ไม่ใช่หลัง flag.**
ชุด control รันก่อนเสมอ (30 เคส, ~4 วินาที) และถ้าเคสไหนตกคนละฝั่งของเส้นตัดตัวเอง
**สคริปต์ไม่พิมพ์คำตัดสินสักบรรทัดแล้ว exit 3**. เคสมีทั้งของสังเคราะห์ที่รู้คำตอบอยู่แล้ว
