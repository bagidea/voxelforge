# Hero scene: "beach-dusk" — outdoor evaluation plate

Status: **design + data file done, Rust wiring NOT done** (no cargo build was run this

## 0. Why this scene exists

Every current beauty/look plate (`docs/assets/look/*.png`, `docs/assets/beauty-board.png`)
is a narrow interior room — no sky, no water, no foliage. The CEO's reference photo
(`workspace/uploads/1786952280558_773223404_122312179466226047_9178907560287775136_n.jpg`)
is a golden-hour beach cabin: warm gradient sky with pink clouds, reflective ocean,
a distant island silhouette, a wooden dock with a boat, sand foreground, jungle trees,
a campfire, hanging lanterns, flower pots. Roughly half of what sells that image is
things our interior plates structurally cannot contain (sky, water, distance). This
scene is the new outdoor measurement plate to replace/complement the kitchen shot.

## 1. How scenes are actually built here (read this before touching anything)

Confirmed by reading the code directly (file:line citations below), not assumed:

- **Map files (`maps/*.json`) are pure voxel geometry** — `version`, `name`,
  `size.chunks_x/z`, and a flat `blocks[]` list of `{x,y,z,block}`. Nothing else.
  No entity list, no lighting, no camera, no props. Schema: `maps/FORMAT.md`,
  Rust struct `client/src/mapfile.rs:19-46`.
- **Loading**: `client/src/main.rs:1364` `load_map_file` → `mapfile::parse`;
  `client/src/main.rs:1269` `apply_map_blocks` stamps blocks into the live `World`.
  Boot entry: `client/src/main.rs:830` `fn setup`, map branch at `main.rs:859-885`.
- **Which map loads by default for `--play`**: hardcoded constant
  `client/src/scene.rs:42` `pub const PLAY_MAP: &str = "maps/edhari.json";`.
  Override any time with the env var `VOXELFORGE_MAP_LOAD=maps/beach_dusk.json`
  (wins over `PLAY_MAP`, see `main.rs:434-436`) — **this is the zero-code way to
  preview this new map**, once someone can run cargo again.
- **Sun**: hardcoded initial spawn `client/src/main.rs:912-919`
  (`illuminance: 9000.0`, `Transform::from_xyz(60.0, 120.0, 40.0).looking_at(Vec3::ZERO, Vec3::Y)`),
  then re-driven every frame by `client/src/look.rs:2648-2696` `apply_look_to_sun`
  from the active `Hour` preset (`look.rs:1388-1416` struct, default preset
  "late-afternoon raking sun" at `look.rs:1445`, `sky`/`sky_gain` at `look.rs:1521-1522`).
  The map file carries **no** lighting data — sun angle for this scene is a `Hour`
  preset choice in Rust, not something `beach_dusk.json` can express.
- **Camera, spawn point, campfire, any encounter**: all hardcoded per-map logic in
  `client/src/scene.rs:432-532` (`fn boot_scene`). Spawn point is *searched for*
  (`scene.rs:545-567` `map_spawn`, spirals from map center for a standable column),
  not stored as data. Campfire mesh/material is hand-built Rust
  (`scene.rs:663-739` `spawn_campfire`) placed `FIRE_AHEAD = 3.0` voxels
  (`scene.rs:61`) in front of whatever spawn point was found. This is the existing
  precedent for "prop that isn't in the block grid" — beach-dusk's boat/campfire/
  flower-pots should follow the same pattern (hardcoded Rust prop, keyed off the
  map's `name == "beach-dusk"`, not new JSON fields).
- **`shot_main.rs`/`hero.rs`/`char_shot_main.rs` never touch `maps/` at all** — they
  render fully hand-coded hardcoded rigs selected by env var
  (`VOXELFORGE_VFX`/`VOXELFORGE_CHARSHOT`/`VOXELFORGE_ENEMYSHOT`, else default
  `hero::setup_hero`, see `client/src/shot_main.rs:241` and the doc comment at the
  top of that file). **This is the more natural home for a beach hero-shot rig**
  than the gameplay map/scene.rs path, since it's a still-image measurement plate,
  not something the player walks around in. Recommendation in §5.

**Bottom line**: terrain geometry is genuinely data-driven (done, see §2). Sun angle,
camera framing, water, and small props are not data-driven anywhere in this engine —
they are Rust code, same as every other scene here. This doc specs that code; it does
not pretend the JSON file alone produces the shot.

## 2. Terrain data file — DONE

`maps/beach_dusk.json`, generated by `scripts/gen_beach_dusk_map.py` (deterministic,
re-run any time to regenerate). 3,378 blocks, 2×2 chunks (64×64 voxel footprint,
matching `edhari.json`'s scale), validated against the schema (correct block names,
in-bounds coordinates). Layout, in world-voxel coordinates, `+Z` running from the
tree line toward open water:

```
z  0-14   grass yard / tree line          (inland, spawn/path area)
z 15-40   sand beach, sloping to shore     (waterline at z=40)
z 41-63   water trench — deliberately left as air/void, no blocks placed
```

- **Cabin**: hollow wood-wall box, `x 24-34, z 16-24`, walls `y 1-6`, flat brick
  roof cap at `y 7`, door gap in the beach-facing front wall (`z=24`) at `x 28-29`.
- **Path**: `dirt` strip at `x 28-29`, `z 0-24`, from the map edge to the cabin door.
- **Dock**: wood walkway `x 29-31` from the cabin's front wall (`z=24`) out to
  `z=48` — i.e. it runs 8 voxels out over the water trench. Support posts at
  `x=29,31`, `y=0`, every 6 voxels of `z`; `lamp` blocks (already emissive in-engine,
  see §4) top those same posts at `y=2` as dock lanterns — **this is real map data**,
  since `lamp` is a valid block type, unlike water/boat/campfire.
- **Trees**: 5 trunk+canopy clusters (`wood` trunk `y1-3`, `leaves` canopy `y4-6`)
  flanking the yard and one on the island.
- **Island**: an isolated `sand` mound at `x 50-58, z 54-61` sitting alone out in the
  water trench, with one small tree on it — echoes the reference photo's distant
  island silhouette.

Verified: `python -c "json.load(open('maps/beach_dusk.json'))"` parses cleanly, all
3,378 block names are in the FORMAT.md palette, all coordinates are in
`[0,64)×[0,32)×[0,64)`. **Not yet loaded in-engine** (no cargo run this pass) — do
that first via `VOXELFORGE_MAP_LOAD=maps/beach_dusk.json` before trusting the visual
layout, and adjust the generator script (not the JSON by hand) if the proportions
read wrong in-engine.

## 3. Camera & sun

**Camera**: elevated 3/4 view from the beach side, looking across the cabin toward
the dock/water, mirroring the reference photo's composition (house center-left,
dock+water opening to the right, trees framing the left edge). Concretely, for a
`hero`-style static rig (see §5):
- Position: `(18.0, 10.0, 6.0)` (world voxels) — beach-side, moderate height, well
  back from the cabin.
- Look-at target: `(29.0, 4.0, 30.0)` — roughly the cabin/dock midpoint, so the
  water trench (`z>40`) fills the right third of frame and the sand foreground
  reads in the bottom third.
- This is a starting point, not a locked number — tune in-engine once loadable
  (`VOXELFORGE_CAM` env override exists for the hero rig, see `hero.rs:683`-style
  overrides already used by `shot_main.rs:90-113`).

**Sun**: low golden-hour angle, warm color, coming from behind/side of camera-left
so the water gets a specular glint and the cabin/trees rim-light — same intent as
the existing "late-afternoon raking sun" `Hour` preset already in `look.rs:1445`.
Do **not** invent a new lighting system for this: reuse that preset (or a new
`Hour` preset cloned from it with a lower sun elevation) via
`client/src/look.rs:2648-2696`. If doing this through the isolated hero-shot rig
instead of gameplay `Hour`, use the existing `VOXELFORGE_SUN=elevation,azimuth,illuminance`
env override already wired into `hero.rs:683` / `characters.rs:982` / `enemies.rs:802`
— pick a low elevation (roughly 8-15° above horizon) and an azimuth that backlights
the water from camera-left, per the reference photo.

## 5. Water — the one real gap, concrete plan

There is no water rendering of any kind in this codebase today. Two options, in
order of recommendation:

**A. Reflective quad (recommended, cheap, matches existing engine complexity level)**
Spawn a single large `Plane3d` mesh (or a `Cuboid` with near-zero height, consistent
with how `scene.rs` already builds simple primitive props) covering the water
trench footprint (`x 0-64, z 40-64`, `y ≈ 0.4` — just above void level so it reads
as a filled surface, not a floor). Material: `StandardMaterial` with a blue-teal
base color, low `perceptual_roughness` (~0.05-0.15) for a sharp specular sun glint,
and `EnvironmentMapLight`-driven reflections — this IBL component **already exists
and is already wired to the camera** (`main.rs:3032`, `look.rs:2991-3013`), so a
low-roughness plane under it gets real reflections for free without writing a new
shader. Add a slow UV-scroll or vertex-wobble system only if the static reflection
reads too flat in-engine — start static, it's cheaper and may be enough at this
camera distance.

**B. Custom shader (skip unless A visibly fails)**
A `.wgsl` water shader (waves, foam, refraction) — there is no existing shader
infrastructure to build on (repo has zero `.wgsl` files), so this is a much bigger
lift with no precedent to follow. Don't reach for this until option A has actually
been shot and judged insufficient.

Implementation note: keep the water spawn keyed to `map.name == "beach-dusk"` (or
to the hero-shot rig selection in §5.1) exactly like `spawn_campfire`/
`spawn_guard_husk` are keyed to `from_map`/`edhari` today (`scene.rs:487-503`) —
don't make it a generic per-map feature until a second scene needs it.

## 5.1 Recommended integration point

Given §1's finding that `shot_main.rs`/`hero.rs` already exist specifically for
hardcoded still-image measurement plates (no map file, own camera/sun env overrides,
same rig style as the kitchen shot this scene is meant to replace/complement), the
lowest-risk path is:

1. Add a new hardcoded rig module (e.g. `client/src/beach.rs`, mirroring
   `hero.rs`'s structure) that either (a) loads `maps/beach_dusk.json` terrain
   directly via `mapfile::parse` + `apply_map_blocks`-equivalent, or (b) rebuilds
   the same layout as native Bevy spawns like `hero::setup_hero` does for the
   kitchen — (a) is preferable since it reuses the data file from §2 instead of
   duplicating the layout in Rust.
2. Wire a new env selector, e.g. `VOXELFORGE_BEACHSHOT=1`, into `shot_main.rs`'s
   existing selector chain (`shot_main.rs:90-113` region) alongside
   `VOXELFORGE_VFX`/`VOXELFORGE_CHARSHOT`/`VOXELFORGE_ENEMYSHOT`.
3. In that rig: apply the camera/sun from §3, spawn the water plane from §4,
   spawn campfire (reuse `scene::spawn_campfire` if it's reachable from `shot_main`,
   otherwise clone the pattern), boat, and flower pots as hand-built props exactly
   like `hero::setup_hero` already builds its kitchen props.
4. Shoot, compare against the reference photo, iterate on `Hour`/camera constants —
   do **not** touch `scene.rs`'s gameplay `--play` path for this; it's a separate
   measurement rig, same separation the kitchen shot already has today.
