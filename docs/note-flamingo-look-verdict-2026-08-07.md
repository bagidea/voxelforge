## 2. การทดลองชี้ขาด — แยก knob ออกมาวัดเดี่ยว (ไม่ต้อง rebuild)

`client/src/look.rs` มี env lever อยู่แล้ว → ยิง **exe ตัวเดียวกัน (05:38)** สองรอบ เปลี่ยนแค่สองเลข.
ผลคือ rigged-character fix + palette + per-instance variation **อยู่ครบทั้งสองข้าง** — ต่างกันแค่ knob ที่ถูกตัดสิน.

```
VOXELFORGE_LOOK_LIGHT=1.00,0.92,0.62,0.96,0.90,0.48  VOXELFORGE_LOOK_EXPOSURE=10.8   # OLD
VOXELFORGE_LOOK_LIGHT=1.00,0.92,0.62,0.96,0.90,0.45  VOXELFORGE_LOOK_EXPOSURE=10.9   # NEW (shipped)
```

| แกน | เป้า | OLD (0.48 / 10.8) | NEW (0.45 / 10.9) | ทิศ |
|---|---|---|---|---|
| G6 sunlit L | ≥ 55 | 53.1 FAIL | **52.1 FAIL** | 🔻 ถอยห่างจาก floor |
| highlight p95 | 150–185 | 109.7 | **105.4** | 🔻 ถอยห่างจาก target |
| warmth R−B | ≥ 110 | 123.3 | **117.7** | 🔻 เย็นลง |
| micro-contrast | ≥ 5.0 | 5.83 | **5.63** | 🔻 |
| blue B | ≤ 10 | 0.06 | **0.06** | ⏸ **ไม่ขยับเลย** |
| G3 p05-L | ≥ 8 | 14.9 P | 14.5 P | ⏸ |

**ขนาดของการเปลี่ยนแปลงที่ตาเห็น:** mean |Δ| = **3.0 levels / 255**, mean ΔRGB = **−3.10, −1.03, −0.01**, luminance −1.40.
⇒ มืดลงนิดเดียว **แดงน้อยลง** และ **blue ไม่ขยับ** (พื้น 0.06 อยู่แล้ว — ambient B 0.48→0.45 คือ **no-op** บนเพลตชุดนี้).

> **สรุปข้อ 2: สอง knob นี้ในตัวมันเอง ไม่ได้ทำให้ภาพเข้าใกล้ Elden Ring — มันขยับทุกแกนที่มันตั้งใจจะแก้ไปผิดทาง แถมมองด้วยตาไม่เห็น.**
> ความสวยที่เพิ่มขึ้นจริงใน after-set มาจาก **rigged character แทน capsule** + **hue separation ที่ palette คืนมา** ไม่ใช่จากสาม knob นี้.

## 3. ev100 ถูกดันผิดทิศ — ladder พิสูจน์

`look.rs:622` เขียนเหตุผลของ 10.9 ไว้ว่า *"a 0.1-EV nudge for the AAA p95 axis"* และ `look.rs:530` บอกเองว่า ev100 คือคันโยกของ p95.
แต่ **ev100 ขึ้น = ภาพมืดลง = p95 ลง** — เลขที่วัดได้ยืนยัน (109.7 → 105.4). ทิศกลับหัว.

ยิง ladder จาก exe เดิม (ambient B คงที่ 0.45, ขยับ ev100 อย่างเดียว):

| ev100 | G6 sunlit L (≥55) | p95 (150–185) | warmth (≥110) | patch ที่ grader เลือก | R−B |
|---|---|---|---|---|---|
| **10.9 (shipped)** | **52.1 ✗** | 105.4 ✗ | 117.7 ✓ | (1134,788) | **+202** |
| 10.6 | **79.0 ✓** | 118.1 ✗ | 129.3 ✓ | (1126,828) | +187 |
| 10.3 | **82.5 ✓** | 130.3 ✗ | 138.5 ✓ | (1126,828) | +154 |
| 10.0 | **85.4 ✓** | 141.4 ✗ | 143.9 ✓ | (1126,828) | +130 |

**รากปัญหาที่ ladder เปิดออกมา — สำคัญกว่าตัวเลข:** ที่ ev100 10.9 ผิวที่โดนแดดจริง `(1126,828)` **ส้มจัดจน R−B ทะลุเพดาน 210 ของ G6** → grader ตกมันทิ้ง แล้วไปหยิบ patch ที่หรี่กว่าที่ L=52.1 แทน ⇒ G6 FAIL.
พอลด exposure ผิวนั้น **คลายความส้ม** (R−B 202→187→154→130) และสว่างขึ้นพร้อมกัน ⇒ **ผ่านทั้งสอง clause ของ G6 ด้วยคันโยกเดียว**.

นี่ตรงกับที่ตาเห็นในเพลต before: ภาพมัน **สุกเกิน (over-cooked orange)** จนสีอื่นถูกกลืน. knob ที่ ship ไปดันเข้าไปในทางที่สุกขึ้นอีก.

**p95 ปิดด้วย exposure อย่างเดียวไม่ได้** — ถึง 10.0 ก็ยังได้แค่ 141 (เป้า 150). ที่เหลือต้องไปที่ `HIGHLIGHT_GAIN` / `sky_gain` ไม่ใช่ ev100.

## 4. เพลตไหนยึดตัววัดไหน — `grade_hero.py` ตกจากตำแหน่งผู้ตัดสิน

Poppy ตั้งเป็นสมมติฐาน. ผมรันจริงแล้ว ได้เป็น **การวัด**:

**`python scripts/grade_hero.py _poppy_shotset/after/gate3-boot-nohud2.png`**
```
[G6] brightest sunlit wood patches (R>G>B):
  @( 562, 354) RGB=(255.0,179.6, 11.8) L=72.0% R-B=+243.2 x     <- ขอบ rim light ของ "ตัวละคร"
  @( 562, 348) ... R-B=+243.4 x                                  <- พิกเซลข้างกัน
  @( 562, 342) ... R-B=+245.5 x                                  <- พิกเซลข้างกัน
  @( 562, 336) ... R-B=+248.7 x                                  <- พิกเซลข้างกัน
  G6 -> FAIL
[G5] window brightest @(332,12) L=62.7%
  RGB=(130.6,159.2,254.0)                                        <- นี่คือ "ท้องฟ้า" ไม่ใช่หน้าต่าง
```

ข้อบกพร่องที่พิสูจน์ได้ **3 ข้อ** (อ่านจากซอร์สตรงๆ):

1. **G5 ล็อกกรอบว่า "หน้าต่างอยู่ซ้ายจอ"** — `grade_hero.py:54-56` ค้นเฉพาะ `x∈[0.01W, 0.30W]`, `y∈[0.02H, 0.75H]`. บนเพลตกลางแจ้ง กรอบนั้นชี้เข้า**ท้องฟ้า**. บน `hero` มันชี้ไปที่บล็อกน้ำตาลหรี่ L=35% ด้วยซ้ำ. ⇒ ค่า G5 ของ grade_hero บนทั้ง 8 เพลต **ไม่มีความหมาย**
2. **G6 ดูแค่ 4 patch ที่สว่างสุดในกรอบตาย** (`x≥0.28W, y≥0.45H`, `cands[:4]`) — ทั้ง 4 ตัวเป็นพิกเซลติดกันบนขอบ rim light ของตัวละคร มันไม่เคยมองหินทรายเลยสักครั้ง
3. **G6 ของ grade_hero ไม่มี floor `L ≥ 55`** (`grade_hero.py:47` เช็คแค่ hue) — คือ **เวอร์ชันก่อน 2026-08-04** ที่ rubric §G6 clause (ข) ปิดไปแล้ว. ส่วน `grade_gate.py:116` `g6 = sl >= 55` ทำถูกตาม rubric

**ไม่มีเพลตไหนในชุดนี้เป็น "ครัว hero tight" ที่ grade_hero ถูกจูนไว้เลย — ทั้ง 8 ใบเป็น Edhari กลางแจ้ง.**

### คำสั่ง (ในอำนาจผมตาม rubric)

- ✅ **`grade_gate.py` = ผู้ตัดสิน G3/G5/G6 ของทุกเพลตในชุดนี้** (auto-locate + ตรงกับ rubric รวม floor 55)
- ✅ **`grade_look.py` = ตัวยืนยัน** — ตรงกับ `grade_gate` ครบ 8 เพลต 0 mismatch (ตรวจแล้วใน crosscheck)
- ⛔ **`grade_hero.py` ห้ามนับคะแนนบนเพลตที่ไม่ใช่ครัว hero tight** ⇒ ตัวเลข **19→18 (ลง)** ตกไป ไม่ใช่หลักฐาน
- 🔧 **ต้องซ่อม `grade_hero.py`:** เพิ่ม guard ที่หัวไฟล์ให้ **ปฏิเสธเฟรมที่ไม่ใช่ hero framing** (หรือรวมเข้ากับ `grade_gate.py` ไปเลย) + เติม floor `L ≥ 55` ที่บรรทัด 47 ให้ตรง rubric. อย่าปล่อยให้มันเงียบๆ ออกคำตัดสินบนเพลตที่มันอ่านไม่ได้

### แล้ว "hero G5 P→F" (ที่ทั้ง 3 ตัวเห็นตรงกัน) ล่ะ?

**เป็น false regression — พิสูจน์แล้ว.** `grade_gate.py` บน `hero`:
- **before:** `brightest px @(813,213) RGB=(255,0,0)` ← **capsule แดงตัน** ค่า 3 จุดแนวตั้ง spread=11.6 → PASS
- **after:** `brightest px @(1518,375) RGB=(255,35,0)` ← capsule หายไป พิกเซลแดงสุดเลื่อนไปบล็อกผนังขวา spread=3.1 → FAIL

⇒ **เดิม G5 ผ่านเพราะ "บั๊ก capsule"** พอแก้บั๊กเกตเลยตก. เฟรม after ซื่อสัตย์กว่า. ห้ามนับเป็น regression ของ look.

## 5. คำตัดสินสุดท้าย

### `tune-further`

| | คำสั่ง |
|---|---|
| **build ทั้งก้อน (rigged char + palette + variation)** | **KEEP** — 8/8 เพลตดีขึ้นจริงด้วยตา อย่าย้อน |
| **ambient B 0.48→0.45** | **no-op — ย้อนกลับเป็น 0.48 หรือทิ้งไปเลย** ก็ได้ (blue axis 0.06→0.06 ไม่ขยับ) อย่าเสียเครดิตกับมัน |
| **ev100 10.8→10.9** | **กลับทิศ** — ตั้ง **`ev100 = 10.3`** (G6 52.1→82.5 PASS, warmth 117.7→138.5, p95 105→130) |
| **per-instance voxel variation** | **KEEP** — ไม่มี env lever จึงแยกวัดเดี่ยวไม่ได้ ⇒ **ยังไม่มีหลักฐานตัวเลขว่ามันช่วยหรือไม่ช่วย** อย่าเคลมเครดิต |

### 3 อย่างที่ต้องแก้ต่อ เรียงตามน้ำหนัก

1. **`ev100 → 10.3`** (`client/src/look.rs:627`) — คันโยกเดียว ปลด G6 + ดัน warmth/p95 ขึ้นพร้อมกัน มี ladder รองรับ
2. **p95 ที่เหลือ (130→150) ไปที่ `HIGHLIGHT_GAIN`/`sky_gain` ไม่ใช่ ev100** — exposure ตันที่ ~141 แล้ว
3. **ซ่อม/จำกัดขอบเขต `grade_hero.py`** ก่อนที่มันจะออกคำตัดสินผิดให้รอบหน้าอีก

### สิ่งที่ยังไม่ได้พิสูจน์ (พูดตรงๆ)

- แยก contribution ของ **per-instance voxel variation** ไม่ได้ — ไม่มี env lever
- ladder ยิงบน **`gate3-boot` เพลตเดียว** — ก่อนล็อก 10.3 ควรยิงซ้ำอย่างน้อย `hero` + `s1-vista` ให้แน่ว่าไม่ทำ G5 พัง (10.0 เริ่มดัน R ชนเพดานแล้ว)
- ผมยังไม่ได้แตะ `.rs` และไม่ได้รัน cargo ตามที่สั่ง — ตัวเลขทั้งหมดข้างบนมาจาก exe 05:38 ตัวเดิม + env override
